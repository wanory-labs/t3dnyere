# Local validation snapshot

17 November 2026; Rust `1.97.1 (8bab26f4f 2026-07-14)`, Cargo `1.97.1`. This is local prototype evidence, not production certification. CI definition exists but has not been run on GitHub in this session.

## Tested

```sh
cargo fmt --all --check
cargo test --locked
cargo clippy --all-targets --locked -- -D warnings
cargo build --release --locked
cargo run --locked --release --example measure
```

All returned exit 0. Test suite: 13 core/protocol tests + 2 executable CLI tests. Coverage includes primitive analytical points, boolean sign tests, conservative-vs-exact distance counterexample, coincident zero sheets, JSON strict fields, deterministic reordering, missing references/cycles/duplicate IDs, invalid numeric inputs, a 4096-node chain, round-trip field equivalence on a sample grid, every truncation of a sample asset, malformed decoder inputs, preview visibility/determinism/bounds, MCP lifecycle/error categories, and CLI JSON/stdin/error behavior.

A separate Python standard-library subprocess smoke check used a temporary output directory to verify:

- JSON stdin → compile → 52-byte sphere asset → inspect/sample/32² preview.
- Second compile to the same path fails and leaves original bytes unchanged.
- MCP executable handshake, tools/list, compile_model and sample_model.
- MCP hex-decoded asset equals CLI-compiled bytes exactly.
- CLI schema contains all five operation variants.

No actual Codex or DSH client was connected. This validates the subprocess protocol, not vendor-specific configuration or GUI behavior. The server is deliberately a small subset, not a full MCP conformance implementation.

[Bracket preview](<bracket-preview.png>) was generated by the release CLI at 192², then converted from PPM to PNG using macOS `sips`, and visually inspected. It shows a box with a spherical cavity. This demonstrates one CPU-rendered model, not general renderer robustness.

## Storage experiment — Tested

Source: [measure.rs](<../examples/measure.rs>). One unit sphere centered at origin.

| Representation | Bytes | Detail |
|---|---:|---|
| Source compact JSON | 105 | One sphere node, stable ID |
| T3D v1 | 52 | 20-byte header + one 32-byte record |
| Raw mesh position f32 + index u32, 8×16 | 4056 | 114 vertices, 224 triangles |
| Raw mesh position f32 + index u32, 32×64 | 71448 | 1986 vertices, 3968 triangles |

Single release-run timing observed: 10000 decode calls total 788 µs; 100000 sample calls total 7186 µs. Includes allocation; `black_box` used. These are **one-run totals**, not robust median/p95 latency, not cross-machine baselines and not an end-to-end runtime benchmark. Do not use these numbers as performance guarantees.

Mesh buffers exclude container metadata, normals, UV and materials; they are uncompressed. An analytic sphere and a tessellated sphere have different surfaces. No rate-distortion comparison, meshoptimizer/Draco run, compressed source comparison, GPU FPS or resident-memory measurement was performed. The evidence only establishes these concrete output sizes and that the experiment executes.
